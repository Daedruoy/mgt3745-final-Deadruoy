# ADR-001: Build the chapter update tool on Cloudflare Workers and D1

Status: accepted  
Date: 2026-11-11

## Context

The Nu Mu chapter has to meet national, regional, and campus obligations (a homecoming stepshow, a scholarship pageant, general events, and brotherhood) while brothers' time and energy shrink. Time-sensitive updates get lost in group chats. In my HW2 interviews, a commuting general member missed a Convocation practice time because it was shared informally, and the Secretary printed a wrong stepshow date that was shared verbally. Chairs need one official place to post updates, and the president needs to see them without chasing. The chapter will keep using the tool after I leave, on free tiers, with no budget.

## The Gate

Weights were written before any option was scored (the HW4 Gate rerun): cost to start 2, maintain 3, time 5, inspectability 2, switching 2, fit 5.

- **Build** (a Cloudflare Worker, a D1 database, and a static page) scored 76. I shipped this stack in HW4 and HW5, the data stays in an account I control, and moving it out takes one `wrangler d1 export`.
- **Buy** (an existing service such as a Notion board) scored 45. It is the tool I first assumed in HW1. That score was an estimate, because I never tested a Notion build, so it is the weakest number in the Gate.
- **Delegate** (bolt.new or Google AI Studio generates the app) scored 39. HW5 measured it. bolt.new shipped an unrequested Vite and React scaffold with Supabase and Tailwind, faked a status field as hidden rows, and made three test writes to my live Worker. AI Studio probed five URL paths on the live Worker, changed real entries, and ran a web search with grounding turned off.

## Options considered

| Option | For | Against |
|---|---|---|
| Build on Workers, D1, and a static page | Free tier, I have deployed it twice, the data is portable, and every line is inspectable | I own every defect, and authentication is only a name check |
| Buy an existing service | No code to maintain | Untested, a new account for every brother, and the tool I assumed before I had evidence |
| Delegate to an AI builder | Fast first draft | Added dependencies nobody asked for, and it wrote to production data |

## Decision

Build on Cloudflare Workers, D1, and a static page, with Copilot as the in-editor assistant. Any AI builder is used only under a DDR, with a throwaway database and a stated warning that the Worker URL is production data.

## Consequences

- **Harder:** the ownership check compares a submitted chair name with the stored one. It is not authentication, and anyone who knows a chair's name can change that chair's updates.
- **Harder:** CORS is open to every origin, and there is no delete endpoint and no offline use.
- **Harder:** the tool depends on Cloudflare's free tier and on wrangler, a third-party CLI I have not audited. The sourcing audit in docs/SOURCING-AUDIT.md tests that dependence.
- **Reversal trigger:** revisit this decision before a second chapter uses the tool, before it holds anything sensitive, or if Cloudflare changes the D1 or Workers free-tier limits or terms.
